# Vipiski (остатки по выпискам)

Новый конвейер: PDF → лист **Raw_balances** в Google Таблице → итоги по компаниям в **Account_balances** → Telegram.

Старый скрипт `Vipiski_ostatki.py` (Excel + xlwings) оставлен для справки; рабочая точка входа — `main.py`.

## Логика работы (согласованность шагов)

1. **Входящие PDF** — все файлы из папки `Текущие` (или `VIPISKI_SRC_DIR`) рекурсивно копируются в архив `…/ГГГГ-ММ/ддммгггг/`. Удаляются **только** те файлы во входящей папке, которые успешно скопировали (ошибка копирования не приводит к потере выписки).
2. **Парсинг** — для каждого PDF извлекается текст; правила счетов перебираются **в порядке списка**; первое совпадение всех подстрок `match_all` выбирает правило; срабатывает один парсер на файл (аналог цепочки `elif` в старом скрипте). Несколько PDF за день могут обновить разные `account_code`; повторно тот же код — побеждает последний обработанный файл (порядок — сортировка имён файлов).
3. **Raw_balances** — читаются текущие строки `account_code` / `balance`, поверх накладываются значения из PDF, таблица перезаписывается целиком с сортировкой по коду. В таблицу попадают только коды, которые уже были в Raw **или** пришли из PDF этого запуска (лишние счета не создаются нулями при первом запуске).
4. **Account_balances** — для каждой активной компании суммируются остатки по списку её счетов; в ячейку `google_total_cell` записывается **число** (не формула). Если Raw пуст и PDF ничего не распознал, **ячейки итогов не трогаются** (чтобы не обнулить таблицу).
5. **Депозиты** — по-прежнему читаются с основного листа (колонки A, G, J), как в старом коде.
6. **Telegram** — текст строится по секциям и счетам; если в Raw нет данных и PDF пуст, сообщение **не отправляется**. Длинный текст режется на части (~4000 символов).

Подробные пояснения по каждому шагу — в модульных докстрингах в `main.py` и в пакете `vipiski/` (на английском, в исходниках).

## Быстрый старт

1. Установите зависимости: `pip install -r requirements.txt`
2. Укажите токен Telegram, ID чата и путь к JSON в файле **`.env`** (можно скопировать из `.env.example`) или правьте сразу `.env.example`: загружаются **оба** файла, приоритет у `.env`. Имя таблицы с пробелами — в **кавычках**, например `GOOGLE_SPREADSHEET_NAME="Копия План_платежей (день)"`.
3. Положите ключ в `credentials/service_account.json` (или путь в `GOOGLE_CREDENTIALS_JSON`).
4. Выдайте сервисному аккаунту доступ к таблице (редактор).
5. При первом запуске в книге появится лист **Raw_balances**. При необходимости перенесите в него стартовые остатки по счетам (`account_code` как в коде), иначе до первых распознанных PDF итоги в колонке D не обновляются (защита от обнуления).

## Запуск

```bash
python main.py
```

PDF кладите в `<VIPISKI_BASE_PATH>/Текущие` — файлы копируются в папку дня и удаляются из входящей только после успешного копирования.

## Настройка счетов и компаний

Пустые `config/accounts.json` и `config/companies.json` (массив `[]`) означают использование встроенного реестра в `vipiski/registry.py`. Чтобы править без кода, заполните эти файлы массивами объектов (см. структуру в `registry.py`).
